# 砚芽 · 玄境 / Yanya Xuanjing

> 一座随着陪伴与记忆缓慢生长的岛。

这是砚芽的**独立前端重构实验仓**。旧版砚屿 `tusumy/aevren-xy` 保持原状，避免在新架构尚未稳定时损坏日常使用的聊天、书房、API 与 MCP。

## 核心设定

- **东方灵境为骨**：山、海、灵圃、藏书阁、节气、签文。
- **西式神秘学为光**：星图、月相、塔罗、天文仪与银色星轨。
- **陪伴为核心**：岛屿不替代聊天；岛上的建筑只是通往功能的空间入口。
- **日积月累的变化**：时间、季节、收藏、纪念、主动保存的记忆，让岛屿呈现不同状态。
- **美观不妨碍效率**：所有主要入口可直接访问；动画可降低或关闭。

本仓采用无构建依赖的静态原型（HTML/CSS/JS），方便通过 GitHub Pages 查看，之后再根据稳定性决定是否引入组件化构建工具。

已实现（Seed 01 + Seed 02）：

## 开发原则

1. 新旧项目**不共用存储键或 Android applicationId**。新原型使用 `yanya.xuanjing.*` 命名空间。
2. 新版本不可在没有迁移策略的情况下覆盖旧砚屿的数据；导入流程要支持备份与预览。
3. 数据优先留在本机；绝不在页面源码和仓库里保存 API Key。
4. 若后续使用 Android WebView 壳，可像旧版砚屿一样加载线上静态前端，前端更新不强制重装 APK；原生权限和桥接修改仍需重新发版。
5. 抽签、塔罗和星象作为自我表达与娱乐体验，不制造现实结果保证。

## 运行

直接打开 `index.html` 即可（推荐浏览器/静态网站），也可将根目录部署为 GitHub Pages。首次使用无需安装 Node.js。

## Seed 24 · MCP、消息操作与旧版备份迁移

- MCP 管理：添加、编辑、启停、删除、连接与工具目录；Streamable HTTP 初始化、会话标识、协议版本协商及分页工具发现。支持 JSON 与 SSE，收到匹配响应后结束流读取，避免长连接一直挂起。Token 只留在 sessionStorage。
- 聊天工具：已启用并连接过的 MCP 工具可由模型调用，执行前展示服务、名称与参数；最多 4 轮，支持停止。工具调用不自动重试，避免写操作重复执行。启用工具时使用非流式模型回复。
- 语音：可选择支持 `text_to_speech` 的 MCP，配置 Voice ID、Model ID 和语音标签；通话与消息朗读共用设置。支持 HTTPS 音频链接与 MCP 音频内容。服务调用可能消耗服务商额度。
- 消息：编辑、删除、收藏到星阁、最后一条回复重新生成；历史记录可搜索和改名。
- 角色：每段对话可以独立指定角色；新对话开场、文字聊天与通话均使用该角色设定和世界书。
- 数据：导出砚芽当前数据，分项恢复；旧版 `AevrenXYBackup` 支持预览后合并聊天文字、角色、世界书、默认开场与记忆。保留导入前快照，支持撤销；写入失败尝试回滚。仅操作砚芽自己的存储键。
- 迁移限制：当前聊天容量 36 段，每段最近 120 条文字，每条 12000 字；角色最多 100 个，角色设定与世界书各最多 12000 字，记忆最多 150 条。以现有内容优先，重复 ID 跳过。旧版图片附件、群聊成员、分支、备选开场、章节、条件触发规则、HTML 显示规则、密钥与账号设置尚未迁移，预览界面明确提示。

```sh
node tests/mcp-data.cjs
node tests/voice.cjs
```

以上为模拟环境检查：覆盖聊天工具闭环、收藏、通话记录、MCP 会话与部分 SSE 数据、已停止请求不执行工具、备份转换、导入回滚，以及 MCP 语音标签、标题与播放结束。真实服务商 CORS、设备麦克风与手机布局仍需实际设备验收。

## Seed 27 · 图片与文本附件

- 聊天输入区增加「＋ 附件」；发送前可预览和移除。支持 JPG/PNG/WebP 图片，及 TXT、Markdown、JSON、CSV、代码等文本文件。每条最多 4 个附件，其中图片最多 2 张；图片在本机缩放压缩，文本每份最多 8000 字。不读取 PDF、Word、压缩包。
- 图片使用 OpenAI 兼容 `image_url` 视觉格式；文本文件随正文和文件名发送。图片需要服务商所选模型支持视觉；不会在失败后静默丢图重发。
- 附件随消息保存，包含在对话导出和数据 JSON 备份中，刷新后继续显示与参与上下文。对话备份导入大小上限增加为 24 MB。
- 切换对话时在当前页面分别保留文字与附件草稿；通话不消费聊天草稿。草稿尚未发送前不跨刷新保存。
- 本机存储不足时不清空用户草稿、不发起模型请求；回复已收到但保存失败时保留本页可复制/导出的回复并提示。对话导入超出 36 段时拒绝合并，避免覆盖已有记录。
- 新增 `node tests/attachments.cjs` 和 `node tests/chat-attachments.cjs`，覆盖附件校验、视觉/文本请求格式、JSON 往返、文件发送保存与存储失败草稿保留；已接入发布检查。图片实际压缩效果、文件选择器及手机布局仍待设备验收。


## Seed 28 · 表情、语音条与分支

### 表情包架

聊天「表情」入口支持上传 JPG/PNG/WebP/GIF、改名分类、搜索、删除和表情 JSON 导入导出。每架最多 32 张、总数据约 1.5 MB；GIF 保留原动画，文件不超过 130 KB，大静态图本地压缩并保留透明通道。点选后放进待发送区，由用户点发送。表情目录可供模型通过 `[[sticker:ID]]` 选择回复表情；模型依赖表情名字理解含义，不发送 GIF 的像素内容。表情包架包含在数据备份里，已经发送的表情不随架子删除。

### 语音条

- 「录音」打开录音面板，最长 60 秒。录音后试听、编辑文字、放入待发送区；可显式使用当前聊天接口的 `/audio/transcriptions` 转写，默认模型名 `whisper-1`，可手动改名，服务需支持且可能计费。未转写时给聊天模型明确的语音占位说明，不假装模型已听懂原始录音。
- 消息上的「保存语音条」用所选 MCP 音色生成，包含语音标签和标题；将音频下载成本机消息数据。系统朗读不能导出音频，MCP 音频链接需要允许浏览器下载，单段不超过 650 KB。
- 保存的录音和生成语音均支持音频控件、按住播放/松开暂停、下载与查看转写文字，包含在聊天/数据 JSON 备份中。音频模式会优先停止其他已播放语音。录音开始需要明确点击，取消、停止与关闭聊天会释放麦克风。

### 回复版本与对话分支

最后一条回复可重新生成，原回复保留为版本，最多 12 个；新请求失败时保留原回复。上下版本按钮选择活动答案，后续请求仅发送当前版本。中途选择旧版本会创建新对话，保留原有后续内容；每条消息也提供「从这里分支」。版本和分支随备份保存，对话容量满时先提示清理，不自动删除原对话。

新增检查：`node tests/branches-media.cjs`、`node tests/chat-branches.cjs`、`node tests/voice-notes.cjs`。模拟检查涵盖版本和分支隔离、版本保存、表情目录/标记解析、GIF 数据保留、语音附件格式与转写载荷、录音权限取消时释放麦克风、录音停止/转写/添加及清理。实际手机麦克风、音频播放手势、GIF 动画和服务商转写仍需设备验收。


## Seed 29 · 书房、创作角和聊天菜单

### 书房

保留原有角色设定、固定世界设定、头像、用户名字和存储键。新增最多 12 个备选开场，可选择新对话使用哪一个；支持占位符。世界书提供独立条目、关键词任意/全部匹配、常驻/启停、顺序调整、1–20 条近期消息扫描和触发测试。触发正文预算 12000 字，超额条目在触发测试中列出；固定设定仍每次发送。

章节正文单独保存，只有勾选的摘要加入聊天，摘要正文总预算 8000 字。摘要可手写，也可点击调用当前接口生成一句话摘要；正文不自动加入每次请求。原有书房备份继续兼容，新增字段随书房和完整数据备份保存。

### 创作角

首页「✎」和聊天「更多 → 创作角」打开独立书架；一本书一套世界，可多选角色，模型以统一叙事呈现所选角色。每本最多 12 条独立故事线，可以复制故事线保留另一个走向。正文可收为章节、手工编辑、生成摘要，并选择哪些摘要带入后续创作；新故事线可携带已有章节摘要衔接剧情。每线最多 120 条消息和 40 个章节，达到消息容量后提示新建故事线，不自动删除旧正文。

创作角使用独立 `creation-books.v1` 数据，不写入岛心聊天；支持设定书 JSON 单独导入导出以及完整数据备份。默认书架容量 30 本，书本中的角色 ID 引用书房角色，跨设备请同时备份书房。摘要和创作使用当前 OpenAI 兼容接口，以非流式文本模式请求，不自动调用 MCP 工具；可能消耗接口额度。

旧砚屿完整备份新增迁移：备选开场、世界书关键词与常驻规则、章节摘要以及创作角世界/角色/故事线；旧创作分节作为章节保存。数据预览列出容量限制，旧备份保留。

### 菜单与检查

聊天上方精简为角色、通话和更多，表情、语音设置、书房、创作角、MCP、备份和外观统一收进菜单。离开书房/创作页面会取消相关生成请求，过期请求不覆盖新页面数据。

新增 `node tests/library-creation.cjs` 与 `node tests/completion.cjs`，覆盖世界书触发规则/扫描范围、开场与摘要上下文、旧字段兼容、多角色创作收发、章节摘要、故事线隔离、日常数据不被改写及摘要请求的接口/授权/取消行为。全部接入发布检查。真实手机布局与实际接口的生成效果仍待设备验收。
